# Helamin — сайт компании

Восстановление сайта после JS-инъекции. Цель — сохранить информацию, сделать
адаптивный интерфейс и не допустить повторной инъекции: минимум зависимостей,
никаких внешних скриптов, контент проходит санитизацию перед выводом.

Вся документация лежит в `docs/`. Пути в таблицах ниже указаны от каталога
`helamin-laravel/` (само приложение), а не от корня репозитория.

## Стек

- Laravel 13 / PHP 8.3+
- Filament 5 — админка для менеджеров (в `require`, работает при `--no-dev`)
- Blade + чистый CSS (`public/css/app.css`, `public/css/media.css`) + минимальный свой JS
- Markdown для контента: `league/commonmark` уже входит в Laravel, новых пакетов нет
- SQLite локально, MySQL на хостинге

## Админка для менеджеров

Вход: `/admin/login`. Попасть может только пользователь с `is_admin = true`
(`User::canAccessPanel()` + `AdminMiddleware`).

Менеджеры редактируют **только контент**:

- заголовок, текст (Markdown), meta description;
- несколько картинок за раз (JPG, PNG, WebP, GIF, AVIF; SVG запрещён);
- несколько PDF за раз;
- фон сайта (только на главной странице);
- вставку файла в текст **одной кнопкой** — «Вставить файл в текст» под редактором.

**Менеджер никогда не пишет путь к файлу.** После загрузки и сохранения страницы
файл автоматически попадает в медиатеку (`media`) и получает неизменный ID.
Кнопка вставляет в текст готовый Markdown: `![Описание картинки](/media/12)` или
`[Название документа](/media/12)`. Роут `/media/12` сам подставляет актуальный
файл из БД (`media.file_path`). Если хостинг или FTP-клиент переименовал файл,
достаточно поправить одно поле `file_path` в записи медиатеки: неизменный якорь
`path`, все тексты и вставленные в них файлы продолжают работать. Уже набранные
старые ссылки `/storage/...` при выводе автоматически заменяются на
`/media/{id}` (`Page::stabilizedContent()`).

**Автоматических блоков с файлами больше нет** — ни галереи под текстом на
публичных страницах, ни секций «Картинки / Готовые ссылки на документы» в
«Просмотре» админки. Все файлы появляются только там, где менеджер вставил их
в текст кнопкой: картинка — на месте ссылки, PDF — мини-превью с просмотром
на весь экран.
Подписи файлов задаются в разделе админки **«Медиатека»** (`/admin/media`):
там же правится `file_path`, если хостинг переименовал файл. По умолчанию кнопки
используют понятные «Описание картинки» / «Название документа», а не ULID-имена.
Создавать и удалять записи в медиатеке нельзя — они появляются только при
загрузке файлов на страницах, иначе существующие ссылки `/media/{id}` пропали бы.

> Загружать файлы нужно только через админку. Если положить файл по FTP напрямую,
> он не попадёт ни в `pages.images/documents`, ни в медиатеку — сайт о нём не
> узнает, а хостинг может ещё и переименовать его.

Менеджеры **не меняют структуру**: поля `slug`, `type`, `is_active` убраны из формы,
создание и удаление страниц запрещены на уровне `PageResource::canCreate()` /
`canDelete()`, кнопки удаления убраны из шапки редактирования. Главная страница
дополнительно защищена в `Page::booted()` — её нельзя удалить даже из консоли.
Новую страницу добавляет разработчик: строка в `PageSeeder` + именованный роут
в `routes/web.php`.

Вёрстка формы (начиная с `lg`): сетка из 3 колонок, редактор текста занимает
2 колонки слева, все остальные блоки собраны в `Group` с `columns(1)` и идут
**строго вертикально** в правой колонке (картинки, PDF, фон, SEO). На
мобильном всё складывается в одну колонку. Значения заданы числами
(`columns(3)`, `columnSpan(2)`, `columnSpan(1)`), а не массивами с `md` —
иначе Filament сохранял дефолтный `lg => 2` и блоки расползались.

> Локально `APP_URL` должен совпадать с адресом, на котором открыт сайт
> (`http://127.0.0.1:8000` для `php artisan serve`). URL самого публичного диска
> в `config/filesystems.php` сделан относительным (`/storage`), поэтому превью
> Filament и медиа работают на любом хосте.

## Лента новостей

Страница «Новости» (`/news`) больше не ограничена одним полем ввода. В форме
её редактирования есть **«Лента новостей»** — повторяющиеся блоки (`Repeater`),
которые менеджер добавляет, удаляет и перетаскивает мышкой:

| Поле | Что делает |
|---|---|
| Дата | Подпись над карточкой, произвольный текст («24.11.2026») |
| Заголовок | Название новости, он же подпись свёрнутого блока в админке |
| Картинка | Загружается прямо в блоке, попадает в `storage/app/public/news` и регистрируется в медиатеке → ссылка `/media/{id}` |
| Текст | Обычный текст, без Markdown и HTML; сырой HTML вырезается при выводе |
| Ссылка «Подробнее» | Внутренняя (`/раздел`) или `https://…`/`mailto:`; остальные протоколы отбрасываются |

Поле «Текст страницы» остаётся вступлением над лентой. Блоки хранятся в
`pages.blocks` (`longText` + cast `array`, как `images`/`documents` — JSON-колонки
на MySQL хостинга не используются). Публичный вывод —
`partials/news-feed.blade.php` и стили `.news-feed*` в `public/css/app.css`:
вертикальная лента с маркерами-точками, карточками и адаптивом.
`Page::feedBlocks()` нормализует блоки, санитизирует текст тем же
`Str::markdown` и резолвит картинки через медиатеку, поэтому переименование
файла на хостинге ленту не ломает. Пустые блоки не выводятся.

Лента включена только для `slug === 'news'` (условие в `PageForm` и
`dynamic.blade.php`). Чтобы завести такую же ленту на другой странице, достаточно
расширить это условие — новая миграция или роут не нужны.

## Ограничения файлов и диагностика

- **Размер:** до 10 МБ на файл (`maxSize(10240)` в `PageForm`).
- **Форматы картинок:** JPG, PNG, WebP, GIF, AVIF. **SVG запрещён** из
  соображений безопасности. Документы — только PDF, до 20 МБ.
- Загрузка идёт только через админку (`storage/app/public/images`,
  `documents`, `news`, `backgrounds`); файлы по FTP сайт не увидит.
- Ссылка в тексте — всегда `/media/{id}`. Если хостинг переименовал файл,
  правка только поля `media.file_path`; тексты не меняются.

**Если картинка в тексте не отображается**, почти всегда это не формат и не
размер (они проверяются ещё при загрузке), а отсутствующий файл: его удалили
из формы или переименовали на хостинге, а запись в медиатеке осталась.
Проверка:

```bash
php artisan media:check
```

Команда печатает все записи медиатеки со статусом `✓ / ⚠ НЕ НАЙДЕН`, MIME и
размером, а затем все ссылки на файлы в текстах страниц с результатом проверки.
Дальше либо открыть `/admin/media` и поправить «Фактический путь файла», либо
загрузить файл заново, вставить новую ссылку кнопкой и удалить старую из текста.
В форме редактирования и в «Медиатеке» у таких записей стоит `⚠` и пояснение.

`MediaController` отдаёт картинки с **явным `Content-Type` по расширению**,
поэтому WebP/AVIF корректно показываются даже там, где `fileinfo` определяет
их как `application/octet-stream`.

## Фон сайта

В карточке **главной страницы** (`/admin`) есть секция «Фон сайта»: просто
загрузите картинку, и она ляжет плиткой на все страницы. Можно менять сколько
угодно раз. Плитка не масштабируется, поэтому бесшовный рисунок не ломается
ни на десктопе, ни на мобильном.

**Никакой локальной подложки под текстом больше нет.** Фон приглушается одним
полупрозрачным слоем **на всю страницу** (`body.has-site-background` в
`public/css/media.css`), а `.main-content` при включённом фоне прозрачен и
растянут на всю высоту (`.main` / `.main-content` — `flex`), поэтому исчезли
и белый прямоугольник, и полоса «голой» картинки перед футером. Рисунок
остаётся мягким водяным знаком; яркость регулируется парой `0.78 / 0.64`.
Блока «Документы» и автоматической галереи под текстом больше нет.

Заодно приведена типографика контента в `public/css/app.css`: колонка не шире
860px, крупный H1 с тонкой синей линией, первый абзац как «лид», увеличенный
интерлиньяж и аккуратные ссылки с нижней линией вместо сплошного
подчёркивания; футер отделён мягкой тенью и синей полосой.

## Выдача файлов и превью PDF

`GET /media/{id}` отдаёт файл **напрямую из хранилища** (`MediaController`),
а не редиректом на `/storage/...`. Поэтому картинка и PDF не зависят от
симлинка `public/storage`, `APP_URL` и точного имени файла. Если хостинг
переименовал файл, но сохранил ULID-префикс имени, `Media::resolveExistingPath()`
находит его в той же папке и сам обновляет `file_path`. Если найти не удалось —
запрос пишет предупреждение в лог и возвращает 404, а в «Медиатеке» рядом
с файлом стоит `⚠` и виден путь, который нужно поправить.

Кнопки «Вставить файл в текст» показывают только файлы **текущей страницы**,
которые реально есть на диске, — в текст нельзя вставить заведомо битую
картинку.

Отдельный блок «Документы» под текстом удалён. Вместо него `Page::renderedContent()`
через `decorateDocumentLinks()` находит в отрендеренном HTML ссылки `/media/{id}`
на записи типа `document` и заменяет каждую на **мини-превью первой страницы** —
встроенный PDF-вьюер браузера в уменьшенном `<iframe>`, серверный рендеринг
(Ghostscript/Imagick) не требуется и новых пакетов нет. Ссылки на картинки и
обычные страницы не затрагиваются. Превью живёт прямо в тексте (`span`, чтобы
оставаться внутри `<p>`), поэтому список файлов внизу страницы не нужен.

При наведении на превью (на десктопе) или по клику/тапу документ раскрывается
на весь экран в lightbox, который теперь лежит в `layouts/app.blade.php` и
доступен на любой странице. Закрытие — уводом курсора, Escape, крестиком или
кликом по фону; клик «закрепляет» окно. Без JavaScript ссылка-превью просто
открывает PDF в браузере.

Чтобы `frame-ancestors 'none'` и `X-Frame-Options` не блокировали `<iframe>`,
путь `media/*` исключён из `AddSecurityHeaders` — так же, как `storage/*`.

Если хочется перебрать варианты вручную, без админки: положите файл в
`public/images/` и пропишите `background-image: url('../images/water.jpg');`
в правиле `body` файла `public/css/media.css`.

## Безопасность

- Контент рендерится через `Str::markdown` с `html_input => 'strip'` и
  `allow_unsafe_links => false`: сырой HTML и `javascript:`-ссылки не проходят.
- CSP и `X-Content-Type-Options` ставятся HTTP-заголовком, а не `<meta>`;
  админка и Livewire исключены, чтобы не ломать inline-скрипты Filament.
- Внешних шрифтов и скриптов нет, используется системный стек шрифтов.
- `.env`, `database/*.sqlite`, `storage/logs`, `vendor` не коммитятся.

## Локальный запуск

```bash
composer install
cp .env.example .env
php artisan key:generate
touch database/database.sqlite
php artisan migrate --force
php artisan db:seed --class=PageSeeder --force
php artisan storage:link
php artisan serve
```

Администратора создаёт `AdminUserSeeder` — задайте `ADMIN_EMAIL` и
`ADMIN_PASSWORD` в `.env` (пароль минимум 12 символов).

## Проверки перед клиентскими правками

```bash
composer validate

php artisan test
```
