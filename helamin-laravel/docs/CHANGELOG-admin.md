# Helamin — журнал изменений

## Совместимость миграций со старым MySQL (ноябрь 2026)

На хостинге `php artisan migrate --force` упал с `SQLSTATE[42000]: 1071
Specified key was too long; max key length is 767 bytes` на создании
уникального индекса `media_path_unique`. Причина: `string('path')` = 255
символов в `utf8mb4` = 1020 байт, а старый MySQL/MariaDB без
`innodb_large_prefix` допускает максимум 767 байт на индекс.

- `media.path` и `media.file_path` ограничены до **191** символа (191×4 = 764).
  Реальные пути вида `images/<ULID>.jpg` гораздо короче.
- Миграции `2026_11_24_000000` и `2026_11_24_000001` исправлены до применения
  на других окружениях; `pages.blocks` (`longText`) этой проблемы не имеет.

## Диагностика битой картинки и явный MIME (ноябрь 2026)

На главной не отображалась вставленная в текст картинка `.webp`. Диагностика
показала: запись медиатеки есть, но файл физически отсутствует (удалён из формы
или переименован), `/media/1` закономерно отдаёт 404. Ни формат, ни лимит
10 МБ здесь ни при чём — WebP разрешён и проверяется при загрузке.

- `MediaController::show()` теперь задаёт `Content-Type` по расширению
  (jpg/jpeg, png, webp, gif, avif, pdf) вместо `fileinfo`: на Windows и
  некоторых хостингах WebP/AVIF определялись как `application/octet-stream`
  и браузер не показывал `<img>` даже при существующем файле.
- Добавлена команда `php artisan media:check`: таблица всех записей медиатеки
  со статусом, MIME, размером и ссылкой, плюс проверка всех ссылок
  `/media/{id}` и `/storage/...` в текстах страниц.
- В `/admin/media` и в форме страницы появились явные подсказки про лимиты
  (10 МБ, JPG/PNG/WebP/GIF/AVIF, без SVG) и про то, что делать с `⚠`.
- Тесты на явный MIME для всех шести расширений и на запуск `media:check`.

## Убраны нижние блоки с медиа, исправлен TypeError (ноябрь 2026)

На `GET /admin/pages/2` падало `count(): Argument #1 ($value) must be of type
Countable|array, string given` (`PageInfolist.php:55`): в «Просмотре» поле
`images` пришло одиночной строкой, а `Media::whereIn('path', $state)` ждёт массив.

- Из `PageInfolist` удалены секции «Картинки — готовые ссылки» и «Готовые ссылки
  на документы» — нижний блок с медиа в админке больше не нужен, источник ошибки
  исчез. Остались «Информация о странице», SEO и «Контент».
- Убрана автоматическая галерея под текстом: `@include('partials.page-media')`
  удалён из `dynamic.blade.php` и `home_dynamic.blade.php`, сам частичный шаблон
  и стили `.page-gallery*` удалены. Теперь файлы выводятся только там, где их
  вставили в текст кнопкой, — поэтому блок больше не «появляется на некоторых
  страницах».
- `Page::ensureArray()` / `Page::ensurePathList()` нормализуют строковые и битые
  значения `images`/`documents`/`blocks`; их используют `imageUrls()`,
  `documentLinks()`, `feedBlocks()` и `Media::syncForPage()`. `whereIn()` больше
  не получит строку ни при рендере, ни при `php artisan media:sync`.
- Подсказки в форме и документация обновлены: картинки и PDF нужно вставлять
  в текст, автоматических блоков нет.
- Добавлены тесты на отсутствие блоков с медиа и на старые строковые значения
  в БД (`/admin/pages/{id}` открывается без 500).

## Лента блоков для страницы «Новости» (ноябрь 2026)

- Добавлена миграция `add_blocks_to_pages_table`: `pages.blocks` — `longText`
  с cast `array` (как `images`/`documents`, без JSON-колонок ради MySQL).
- В `PageForm` для `slug === 'news'` появился `Repeater` «Лента новостей»:
  дата, заголовок, картинка (`FileUpload` прямо в блоке), текст (`Textarea`,
  без Markdown для менеджера) и ссылка «Подробнее». Порядок — перетаскиванием,
  `itemLabel` показывает заголовок, пустых блоков по умолчанию нет.
- `Page::feedBlocks()` готовит блоки к выводу: отбрасывает пустые, прогоняет
  текст через `Str::markdown` (`html_input => strip`, unsafe links запрещены),
  резолвит картинки через медиатеку `/media/{id}`, пускает ссылки только по
  белому списку (`/…`, `#`, http(s), mailto).
- `partials/news-feed.blade.php` + `.news-feed*` в `app.css`: вертикальная лента
  с маркерами и карточками, адаптив для мобильных. Подключается в
  `dynamic.blade.php` только на `/news`.
- `Media::syncForPage()` вынесен в `registerPath()` и теперь регистрирует также
  картинки из блоков — `php artisan media:sync` подхватит их на проде.
- Общее поле «Текст страницы» сохранено как вступление над лентой; структура
  страниц, роуты и запрет на создание/удаление страниц не изменились.

## Список файлов убран, превью перенесены в текст (ноябрь 2026)

По просьбе клиента убран автоматический блок «Документы» под текстом — больше
никакого списка загруженных PDF внизу страницы.

- `partials/page-media.blade.php` оставляет только галерею картинок; мёртвые

- `Page::decorateDocumentLinks()` в `app/Models/Page.php` после `Str::markdown`

- Разметка lightbox перенесена в `layouts/app.blade.php` — просмотр на весь
  экран доступен на любой странице, а не только там, где есть блок документов.
- Подсказки в форме, «Просмотре» и документации обновлены: картинки по-прежнему
  выводятся галереей, а PDF надо вставить в текст кнопкой, иначе они не появятся.
- Тесты переписаны под новое поведение и добавлена проверка, что lightbox есть
  даже на странице без документов.

## Единое светлое полотно и типографика (ноябрь 2026)

После удаления локальной подложки проявился настоящий белый прямоугольник —
непрозрачный `.main-content { background: var(--c-bg) }`, а под ним «полоса»
яркого фона до футера (`.main` не был растянут, `footer` уезжал `margin-top:auto`).

- `.main` и `.main-content` получили `flex: 1 0 auto`: контентная область
  занимает всю высоту между навигацией и футером, полоса исчезла.
- `body.has-site-background` теперь приглушает фон **одним слоем на всю
  страницу** (`linear-gradient(0.78 → 0.64)` поверх картинки), а
  `.main-content` при включённом фоне прозрачен. Границы «белый лист ↔
  картинка» больше нет, рисунок виден как водяной знак. `text-shadow`
  у текста убран за ненадобностью.
- Заголовок «Документы» снова тёмно-синий (белый был рассчитан на тёмный
  фон и стал бы невидимым); карточки PDF получили белый фон и тонкую рамку.
- Типографика контента: `max-width: 860px`, `font-size: 1rem`, `line-height:
  1.75`, H1/H2 в фирменном синем с тонкой линией, первый абзац как «лид»,
  ссылки с нижней линией и мягким hover вместо сплошного подчёркивания.
- Футер отделён 3px синей полосой и мягкой тенью вверх, чтобы переход от
  светлого полотна к тёмному футеру не был резким.

## Подложка, прямая выдача файлов и превью PDF (ноябрь 2026)

- Убрана полупрозрачная подложка `body.has-site-background .main-content`
  (`rgba(255,255,255,0.5)` + `backdrop-filter`): она растягивалась только на
  высоту текста и создавала светлый прямоугольник поверх фона. Вместо неё —
  лёгкая `text-shadow` у букв. Плашка у блока «Документы» тоже убрана.
- `MediaController::show()` теперь отдаёт файл напрямую из `Storage` с
  `Content-Disposition: inline`, а не редиректом на `/storage/...`. Картинки и
  PDF больше не зависят от симлинка, `APP_URL` и редиректов.
- `Media::resolveExistingPath()` при отсутствии файла ищет в той же папке
  единственный файл с тем же ULID-префиксом и расширением (типичное
  переименование на хостинге) и сам обновляет `file_path`. Иначе — 404 +
  предупреждение в лог, а не тихая битая картинка.
- В «Медиатеке» (`/admin/media`) появился статус файла `✓ / ⚠` и пояснение;
  кнопки вставки в форме страницы показывают только файлы этой страницы,
  которые реально существуют на диске.
- Документы выводятся карточками с мини-превью первой страницы (встроенный
  PDF-вьюер браузера в уменьшенном `<iframe>`, без новых пакетов) и
  полноэкранным lightbox при наведении/клике (`public/js/app.js`,
  `public/css/media.css`, `partials/page-media.blade.php`). Путь `media/*`
  исключён из `AddSecurityHeaders`, чтобы iframe не блокировался CSP.

### Исправлено после проверки в админке

- Удаление страниц было доступно через `DeleteAction` в шапке редактирования —
  главную страницу удалось удалить. Теперь `PageResource::canCreate()`,
  `canDelete()` и `canDeleteAny()` возвращают `false`, кнопка удаления убрана,
  а `Page::booted()` запрещает удалять главную даже из консоли. Главная
  восстановлена повторным запуском идемпотентного `PageSeeder`.
- Форма перевёрстана: `columns(['md' => 3])`, редактор текста занимает 2 колонки,
  остальные блоки собраны в `Group` в правой колонке и идут вертикально.
- Загрузка картинок «повисала» из-за `APP_URL=http://localhost`: Filament
  отдавал превью с чужого хоста. `config/filesystems.php` теперь использует
  относительный `/storage`, локальный `.env` и `.env.example` приведены к
  `http://127.0.0.1:8000`.
- Удаление прикреплённых PDF срывалось из-за колбэка со строгим типом `string`:
  Filament передаёт и строку, и `TemporaryUploadedFile`. Колбэк теперь
  обрабатывает оба варианта; кастомный генератор имён убран (штатные ULID-имена
  Filament безопасны и уникальны), добавлен `maxParallelUploads(1)` для
  устойчивой массовой загрузки.

## Курсивный логотип и медиатека (ноябрь 2026)

### Логотип

- `HELAMIN` в hero и футере стал наклонным: `font-style: italic`, системный
  «узкий» стек `--font-logo` (внешние шрифты запрещены CSP), `®` уменьшен
  и облегчён. Единый класс `.logo-wordmark`. Толщина по просьбе клиента
  увеличена вдвое: `font-weight: 300` → `600`, наклон сохранён.

### Почему ломались файлы

- Раньше ссылка в Markdown была буквальным путём `/storage/<имя>.jpg`. Хостинг
  переименовывал файл (кириллица, пробелы, регистр, `_1`) — и текст, галерея и
  список PDF разом переставали работать. Загрузка по FTP вообще минула БД.
- Добавлена таблица `media` и модель `App\Models\Media`: один файл = неизменный ID.
  В контенте, галерее и списке документов теперь только `/media/{id}`; роут
  `MediaController::show()` берёт актуальный `file_path` из БД и редиректит на
  `/storage/...`. `path` — неизменный якорь (по нему находятся старые тексты и
  записи `pages.images`), поэтому переименование лечится правкой одного поля
  `media.file_path` без правки контента.
- `Page::stabilizedContent()` автоматически заменяет уже набранные старые ссылки
  `/storage/...` на `/media/{id}` при выводе — править существующие тексты не надо.
  Незарегистрированные файлы по-прежнему отдаются через `Page::mediaUrl()`.
- Контроллер, а не замыкание в `web.php`: `php artisan route:cache` из `deploy.sh`
  не поддерживает роуты-замыкания.

### Админка: одна кнопка вместо ручных путей

- В форме редактирования под редактором появились кнопки «Вставить файл в текст»
  с человеческими подписями (`media.label`, по умолчанию «Описание картинки» /
  «Название документа»). Нажатие само дописывает готовый Markdown в `content`.
- `EditPage::afterSave()` регистрирует загруженные файлы через
  `Media::syncForPage()`; `php artisan media:sync` (встроена в `deploy.sh`)
  разово подхватывает файлы, загруженные до обновления. Команда идемпотентна.
- Раздел «Просмотр» показывает те же стабильные `/media/{id}`, подсказки больше
  не учат менеджеров писать `/storage/...` вручную.
- Добавлен ресурс «Медиатека» (`/admin/media`): человеческие подписи и правка
  `file_path` после переименования. Создание/удаление запрещено, чтобы ссылки
  на файлы не исчезали.
- Галерея и список PDF под текстом остались: часто вставлять ничего не нужно.

### Уточнения по вёрстке

- Сетка формы не применялась: `columns(['md' => 3])` и `columnSpan(['md' => …])`
  не перезаписывали дефолтный `lg => 2`, поэтому текст растягивался на всю
  ширину, а «Картинки» вставали под ним. Заменено на `columns(3)`,
  `columnSpan(2)` у текста и `columns(1)->columnSpan(1)` у правой `Group` —
  теперь слева редактор на 2/3, справа вертикальный стек маленьких блоков.
  Проверяется тестом по реальному HTML (`--cols-lg`, `--col-span-lg`).
- Белая подложка `.main-content` скрывала фоновую картинку: осветлена с
  `rgba(255,255,255,0.86)` до `0.5`, добавлено лёгкое `backdrop-filter: blur(2px)`
  для читаемости текста. Полностью убрать подложку можно удалением одного
  правила в `public/css/media.css`. *(Устарело: позднее подложка убрана
  полностью по просьбе клиента — см. первый раздел этого файла.)*
